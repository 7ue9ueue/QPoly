## Outcome

Tested38 new configurations plus h14/v91 controls across four experiment rounds,
nine native timing jobs and four sanitizer jobs. The best final candidate is
`h14_mullo_bottom`: packed low correction multiplication, compile-time tile
stages, and bottom-stage fusion. Its benefit is modest but repeatable on the
three final EPYC7763 jobs. It is a candidate for AtCoder validation, not a
universal replacement: the final combination has not yet been measured on Intel
or the user's actual AtCoder CPU.

Exact standalone, GCC15.2, AVX2-capped, fresh2^20, ten repetitions per job:

| Final job | h14 median ms | mullo_bottom median ms | Time saved |
| --- | ---: | ---: | ---: |
| 1, EPYC7763 | 6.5428 | 6.4170 | 1.92% |
| 2, EPYC7763 | 6.5497 | 6.4197 | 1.98% |
| 3, EPYC7763 | 6.5422 | 6.3991 | 2.19% |

The separately compiled AtCoder-like `-march=native` standalone saves1.8–2.9%
in the same jobs. The multi-translation-unit research harness saves1.9–2.7%
at2^20 and2.1–2.6% at2^22. Do not pool these profiles or compare their absolute
times with the user's7.9968ms AtCoder result. All final jobs happened to receive
EPYC7763; earlier rounds additionally measured Intel8573C and EPYC9V74.

Assembly alone did not win. The combined large-stage assembly/fixed-bottom
candidate saves1.1–1.5% in the final AVX2-capped standalone, while pure C++
`h14_mullo_bottom` wins all three. Full-loop forward/inverse assembly and compact
twiddle state generally tied or regressed in earlier rounds. Karatsuba shared
is36–37% slower in the capped final standalone and44% slower in its native-ISA
profile; it remains labeled an experimental comparison in the file.

## Research and measurement design

[Environment research](../../work/ntt/h14_explore/environment_notes.md) links the
official language command, GCC documentation and pinned GCC15.2 Docker image.
Relevant AtCoder settings include automatic zero initialization and native CPU
targeting. The June2026 announcement removed the older LTO flag. No current
official CPU model was established, so the new comparison prints CPUID metadata.

Native suite: GCC15.2, the relevant AtCoder flags, no LTO, source O3/unroll
pragmas, and explicit `-march=skylake` for a uniform AVX2 ceiling. This approximates
compiler settings, not AtCoder hardware. Every job records actual CPU, flags,
revision, source/generated/binary hashes, raw samples, and container digest.
The Mac is ARM64; local Clang/Rosetta runs are correctness checks only.

Two warmups, nine samples, rotated/reversed order, sizes2^12,16,18,19,20,21,22,
fresh and reuse modes, identical inputs within jobs. Full cyclic convolution is
timed; allocation/input copies/checksums are excluded. Fresh includes size-dependent
root generation; fixed constexpr metadata is never timed. Reuse primes the exact
implementation. Speedups are relative to h14 within the same job.

## Experiments and early findings

1. Whole-leaf assembly (serial, paired, disposable B used as coefficient scratch),
   stage fusion, compile-time tile traversal, scoped uninitialized scratch,
   alternate odd-lane extraction, split accumulation, tile sizes and leaf unrolling.
   All17 entries passed native tests and ASan/UBSan in
   [round1](https://github.com/7ue9ueue/QPoly/actions/runs/36278509138), source407b79a.
   At2^20 neither CPU showed a convincing gain: Intel8573C h14=8.6277ms,
   best fixed_bottom=8.5397; AMD7763 h14=6.5755, best tile1024=6.5281.
   Split accumulation regressed~3–6%; removing scratch auto-zero initialization
   was neutral. Intel fixed_tile improved~3.5% at2^22 in this job, but this did not
   hold consistently in round2. Retain the observation, not a universal claim.
2. Complete forward radix-4 assembly serial/paired, restricted large-stage
   versions, paired C++ Montgomery chains, and leaf/traversal combinations.
   All14 selected entries passed in
   [round2](https://github.com/7ue9ueue/QPoly/actions/runs/36278897141), sourceead4135.
   Full-stage assembly lost up to~3% at2^20. Restricting it to h>4 recovered most
   of that loss, but h14 remained essentially tied. Best combination
   asm_radix4_pair_large_fixed saved0.8% on AMD and0.4% on Intel: inconclusive.
   Paired C++ chains saved~0.5% on both, also inconclusive.
3. Inverse radix assembly, compact forward twiddle representations, and alternate
   Montgomery instruction selection passed all15 selected native entries in
   [round3](https://github.com/7ue9ueue/QPoly/actions/runs/36279149290), source540b51c.
   On EPYC7763 and9V74, inverse assembly regressed~1–2%, and combined full-stage
   forward/inverse assembly regressed~3–4%. Compact forward twiddles regressed
   ~1–2%. `vpmulld` correction words tied within~0.5%; expanding qP into shifts
   increased time~73–75%. Fewer multiplication instructions alone are not enough.
   The large-stage assembly/fixed-bottom combination again saved0.4–0.8%, a small
   candidate effect that still needs exact-file/target validation. Independent
   formula, range, operand/clobber and address reviews complement runtime checks.
4. Karatsuba weighted-cyclic-eight products and multiply/traversal combinations
   passed all9 research entries in the
   [final run](https://github.com/7ue9ueue/QPoly/actions/runs/36279532832), source25a02b5.
   Both Karatsuba variants regressed~36–37% in the controlled research harness;
   multiply plus fixed/bottom traversal is the best measured combination above.
   The independent Karatsuba
   derivation computes three cyclic-four products and reconstructs even/odd
   coefficients. Sharing weighted preparation reduces duplicated work, but its
   total wide-multiply count before CSE is52 per two leaves, the same as baseline;
   the raw48-vs64 scalar coefficient-product comparison omits reduction and wrap
   costs. See [full operation accounting](../../work/ntt/h14_explore/karatsuba_notes.md).

Coarse phase timing in round1 attributed~54% to the two forward transforms,
~17–18% to leaf products,~25% to inverse,~3% to final normalization, and<1% to
root generation. The instrumentation runs once per tile phase/large group and
checks its output against the uninstrumented kernel. Clock and layout overhead
mean this is diagnostic attribution, not a hardware-counter profile or speedup.

## Correctness and contracts

Cyclic convolution modulo998244353; powers of two64 through2^22; canonical inputs,
32-byte aligned disjoint mutable A/B and caller-owned root storage/state. A returns
canonical results; B is destroyed. Forward range<4P, inverse<2P; direct8 terms
canonicalized before accumulation. No shared mutable static scratch is introduced.

Every native variant is checked against an independent ordinary-modulo radix2
oracle, small brute force, deterministic random inputs, large coefficient
boundaries, guards, repeated calls and changing sizes. Failures exit nonzero.
All three leaf assembly variants also pass393216 direct full-range output lanes.
Forward assembly passes11141120 direct full-range output-lane comparisons;
inverse adds an independent ordinary-modulo formula to the same count.
The two new Montgomery multipliers have2097152 independent direct lane checks.
The Karatsuba pair has524288 direct ordinary-modulo leaf checks, including P and
signed-32-bit boundaries and different leaf roots.
ASan cannot instrument the inline assembly itself: address bounds and clobbers
were independently reviewed and explicit guards/range tests supplement it.

## Standalone deliverable

[atcoder_ntt_h14_compare.cpp](../../work/ntt/atcoder_ntt_h14_compare.cpp) is a single
C++17-or-later file, with eight entries and independent reference checks. Baseline
is now ll_inline_h14, so the speedup column is `speedup_vs_h14`. The original v91
is retained as an additional control. CPU brand and advertised feature bits are
printed; these are metadata, not a replacement for actual execution checks.

| Entry | Purpose |
| --- | --- |
| ll_inline_h14 | Exact algorithm/control from the user's winning previous entry |
| v91 | Historical control |
| h14_fixed_tile | Compile-time tile stages with a bounded per-tile function |
| asm_radix4_pair_large_fixed | Paired forward assembly only for h>4, fixed tiles and fused bottom stage |
| h14_mont_mullo | One packed 32-bit low multiply for all correction words |
| h14_mullo_fixed | Previous multiply change plus fixed tile traversal |
| h14_mullo_bottom | Multiply change plus fixed tiles and bottom fusion |
| h14_karatsuba_shared | Independent algorithmic leaf experiment; not a default recommendation |

Empty input uses2^20/five repetitions/fresh roots. Input `20 10 0` matches the
user's last workload; `20 10 2` measures both fresh/reuse. Max supported log2 is22.
The exact file's SHA256 is
`8cc5cba4c8844a39583559e227ce37dd2a2ccda99227e4e9dda0b35ebd476eb6`.

`verify_atcoder.py` tests the exact source as plain C++17/O2 and with GCC15.2
AtCoder-like flags in separate native-ISA and AVX2-capped profiles, recording
hashes, commands, timings and resources. Native-ISA is explicitly separate:
AtCoder's `-march=native` can enable features beyond AVX2 even when the source
intrinsics use AVX2. No assumption about the actual AtCoder CPU is made.

All three exact-file jobs passed plain C++17/O2 default input, capped
`20 10 2`, native-ISA `20 10 2`, and native-ISA `22 3 2`. Source hashes match.
Plain default resource use was1.73–1.74s wall and36552–36628KiB peak RSS on
these EPYC7763 jobs. That is not an AtCoder runtime prediction. The frozen h14
kernel was also checked token-equivalent to the previous standalone. The older
two standalone file hashes remain unchanged.

## Next questions

Run `20 10 0` or `20 10 2` on AtCoder and retain the CPU/compiler banner. In
particular, measure whether the mullo instruction and bottom fusion help on that
processor; AVX2 instruction costs and compiler scheduling vary. If gains hold,
extract the selected kernel into the main library API separately. Deeper progress
likely needs lower total modular-reduction/data-movement cost: Karatsuba's raw
coefficient-product reduction alone did not achieve that here.
