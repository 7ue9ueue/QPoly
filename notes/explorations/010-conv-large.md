## Target and constraints

[Library Checker convolution_mod_large](https://judge.yosupo.jp/problem/convolution_mod_large):
N, M ≤ 2^24, output length ≤ 2^25 − 1, mod 998244353 (roots of unity only to order 2^23),
10 s. Judge (library-checker-judge sources): `g++ -O2 -std=c++23 -DEVAL -DONLINE_JUDGE
-march=native`, EPYC 7B13 (Zen 3), one logical CPU (`judge.slice` cpuset 0, isolated), 1024 MiB
read from `memory.current` (includes the tmpfs pages of our output), input/output files on tmpfs
mounted without `huge=` (4 KiB pages), wall time by 1 ms cgroup polling. The largest of the 54
tests are N = M = 2^24 (max_random ×2, fft_killer ×10, max_ans_zero, all_same ×3), ~331 MB each way.

Leaderboard at start (v3 API, 654 AC): QgQ 403499 0.737 s (575 MiB), Rohan_Kapri 0.742,
anonymous 303498 0.777, adamant ~0.81 (735 MiB). 303498 and 403499 were read for structure only
(both: one length-2^25 cyclic convolution with x^8/x^16 − w leaves and a depth-first radix-4
traversal; 403499 pairs a/b and mixes Montgomery/normal forms); no code was copied. They are
downloaded from the judge API at CI time for timing comparisons and not stored here.

## Research (background agent)

No public design is fundamentally faster than an NTT split to x^k − w leaves (Qwerty1232's
[blog](https://piskareviv.github.io/blog_aux_ntt_1/), [CF 142063](https://codeforces.com/blog/entry/142063);
pajenegod [CF 117947](https://codeforces.com/blog/entry/117947)). Out-of-cache structure:
[Bailey 1990](https://www.davidhbailey.com/dhbpapers/fftq.pdf) (two passes),
[Frigo et al.](https://dl.acm.org/doi/10.1145/2071379.2071383) (cache-oblivious bound),
[van der Hoeven–Lecerf 2024](https://www.texmacs.org/joris/ntt/ntt.html) (+34–52% per butterfly from
2^20 to 2^26 on x86). Doubles ([adamant CF 142860](https://codeforces.com/blog/entry/142860), FLINT
fft_small), Nussbaumer/SSA, Karatsuba/Toom at the top (≥ 7 half-size transforms vs 3 full),
truncated FFT and mixed radix (17·2^21 > 2^25) do not help the max case. In F_p the 4th-root
multiply is not free, so radix changes save passes, not multiplies. The largest untapped lever per
the report is I/O (length-branchless parsing; fixed-width branchless formatting is legal because the
checker ignores whitespace) — outside this exploration, which keeps the 007 I/O by request.

## Kernel rounds (bench_large, NTT only)

`bench_large time 25`: N = M = 2^24 random, one convolution call timed, root tables built inside
the timer, arrays pre-faulted; GCC 15.2 in the pinned image with the judge flags; medians of 7
after 2 warmups, 3 rounds per job; EPYC 7763 jobs used for decisions. Every entry is bit-identical
to `b0` each repetition and passes `bench_large check 25` (textbook oracle and brute force ≤ 2^20;

Per-depth timers (runs 36313058400, 36315509924): the first group 10.7–11.7 ms (memory-bound,
~46 GB/s effective), every forward depth 1–6 9.8–11.6 ms for a+b (1: 10.8–11.6, 2–6: 9.8–10.4),
every inverse depth 4.6–5.0 ms — the same at every depth, i.e. compute-bound (14.4 cycles per radix-4
butterfly); tiles (h = 64, 16, 4, bottom with leaves) ≈ 96 ms, of which the bottom ≈ 52 ms; last
inverse group + scale 7–9 ms (memory-bound). The fused top passes lose because gathering 16–1024
row streams costs more DRAM efficiency than the passes they save; non-temporal stores lose on Zen 3
even for four sequential streams.

QgQ's runner time under `madvise` (751–758 on 7763) matches its judge time (0.737 s); under THP
`always` it drops to 643, so the judge probably runs `madvise`. Our predicted judge time ≈
528 × 737/758 ≈ 0.51 s (about 30% below the current best), assuming the same ratio.

Final phases (probe build, EPYC 7763, run 36315260768): parse (incl. input and arena faults) 90,
NTT 217 (incl. zeroing of upper halves and tables), format + write 207 ms, plus ~12 ms spawn/exit.
Lazy arena: zeroing each huge page right before writing it avoids re-reading prefaulted zeros from
DRAM (−8 to −14 ms per large case on Zen 3, −5 on 9V74, neutral on 9V45). Fusing the depth-0 levels
into parsing/formatting moved the forward group's 11 ms into the parser and slowed formatting by
~35 ms: the memory-bound passes run best as tight streaming loops.

## Decision and next steps

Keep `Core<Sel>::run` + lazy arena + 007 I/O (deliverable above). The NTT is ~205 ms on Zen 3:
~20 ms memory-bound top/bottom-of-recursion passes at bandwidth limit, ~132 ms radix-4 groups at the
exploration-009 rate, ~52 ms leaf stage, ~2 ms tables. Remaining NTT ideas are small: on-the-fly
per-tile twiddles (≤ 2.5 ms + table streaming, bounded by b0zs_keep), a faster fused bottom stage
(36.7 cycles/vector vs ~24 µop floor; exploration 009 search plateaued). The larger remaining lever
is user-space I/O (parse 68 ms, format 87 ms); `write()` into tmpfs (~125 ms) and page zeroing are
kernel costs. Suggested: submit the probe build once to read the judge's phase times and THP mode.
